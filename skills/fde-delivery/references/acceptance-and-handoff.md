# 验收与交接

## 1. 验收原则

- 按 `features.csv` 的 acceptance 逐项验证；
- 用证据说话：截图、录屏、测试记录、对账结果；
- 验收人明确；
- 遗留问题写清楚；
- 不把“演示过”当“验收过”。

## 2. 验收范围

- 主链路；
- 空态/错误态/加载态；
- 权限/未登录；
- 重复提交/弱网（如适用）；
- 数据对账/迁移结果（如适用）；
- 运维：健康检查、日志、备份。

## 3. 验收记录

`docs/acceptance.md`：

| 功能 ID | 功能 | 验收标准 | 结果 | 证据 |
|---|---|---|---|---|
| F-001 | 登录 | 正确账号可登录 | PASS | 录屏 |
| F-002 | 列表 | 搜索/分页/空态 | PASS | 截图 |

结论：

- 通过；
- 有条件通过（遗留问题已确认）；
- 不通过。

## 4. 交接清单

### 代码与文档

- [ ] 仓库地址、分支、最后提交；
- [ ] README / AGENTS / 运行说明；
- [ ] 架构、接口契约、数据模型；
- [ ] features / decisions / roadmap / acceptance。

### 环境

- [ ] 开发/测试/生产地址；
- [ ] 部署目录；
- [ ] 服务器/数据库/账号位置（不写明文）；
- [ ] 证书/域名/防火墙。

### 运行

- [ ] 安装/构建/启动命令；
- [ ] 迁移命令；
- [ ] 健康检查；
- [ ] 日志位置；
- [ ] 备份/恢复；
- [ ] 回滚步骤。

### 已知问题

- [ ] 未完成功能点；
- [ ] 已知 bug/限制；
- [ ] 临时 workaround；
- [ ] 下一步计划。

## 5. 运行手册

`handoff.md` 中至少包含：

```bash
# 安装
# 构建
# 启动
# 迁移
# 健康检查
# 日志
# 回滚
```

## 6. 培训

- 给接手人/业务演示一次；
- 说明权限、边界、常见错误；
- 留下联系人/支持方式；
- 确认对方能独立跑起来。

## 7. 交接后

- 观察期支持；
- 记录问题；
- 更新文档；
- 项目复盘。
