# 知识回灌

## 1. 复盘问题

- 哪些做对了？为什么？
- 哪些返工？根因是什么？
- 哪类需求最容易变？
- 哪个技术选择代价最大？
- 哪些文档没人看/没人更新？
- 哪些验收标准不清楚？
- 下次怎么做得更快/更稳？

## 2. 回灌到 Skill

| 发现 | 回灌位置 |
|---|---|
| 新流程/规范 | `references/` |
| 可复制模板 | `assets/` |
| 确定性操作 | `scripts/` |
| 触发词/范围变化 | `SKILL.md` |
| 版本/变更 | `README.md` 版本记录 |

原则：

- 先改现有文档，不新建平行文档；
- 一条知识只放一处；
- 用真实项目验证过再写；
- 升版本并记录。

## 3. 反模式库

记录“不要这样做”：

- 没有 Non-goals，范围膨胀；
- 功能点只在聊天里；
- 所有功能都 P0；
- 验收标准不可验证；
- 迁移没有对账；
- 上线没有回滚；
- 交接没有运行手册。

## 4. 指标

可选：

- 切片交付周期；
- 返工率；
- 验收一次通过率；
- 迁移对账差异；
- 线上问题数；
- 接手人独立运行时间。

指标用于改进，不用于表演。

## 5. 记忆

- 项目长期方向、约束、决策写项目记忆；
- 代码结构、git 历史不重复写；
- 记忆要能验证，过时及时更新/删除。

## 6. 版本化

- 重要变化升 `version`；
- README 写版本记录；
- 大改后自测触发词、模板、脚本；
- 不把项目专属数据写进 Skill。

## 7. 复盘输出

- 3 条做对的；
- 3 条要改的；
- 1–3 个具体行动（谁、何时）；
- 更新了哪些 Skill 文件。
