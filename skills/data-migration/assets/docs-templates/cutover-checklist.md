# 切换清单

> 项目：__PROJECT_TITLE__
> 计划切换时间：YYYY-MM-DD HH:MM
> 执行人：

## 1. 切换前

- [ ] 迁移计划、映射、对账记录已评审；
- [ ] 源库只读账号可用；
- [ ] 目标库连接、权限、磁盘空间确认；
- [ ] 目标库备份完成，备份可恢复；
- [ ] 最终增量迁移命令与负责人确认；
- [ ] 应用切换/回滚步骤确认；
- [ ] 相关业务方已通知。

## 2. 冻结源写入

- [ ] 通知业务停止写入；
- [ ] 确认无新数据进入（监控/日志/计数）；
- [ ] 记录冻结时间。

## 3. 最终增量

- [ ] 执行最后一次迁移（--apply）；
- [ ] 记录 processed / written / skipped / errors；
- [ ] 失败则停止并回滚，不带病切换。

## 4. 验证

- [ ] 数量对账通过；
- [ ] 金额/汇总对账通过；
- [ ] 抽样对账通过；
- [ ] 关键业务查询验证；
- [ ] 应用登录/主链路验证。

## 5. 切换应用

- [ ] 切换数据库连接/配置；
- [ ] 重启应用；
- [ ] 检查 `/api/healthz`、`/api/readyz`；
- [ ] 检查错误日志和慢查询；
- [ ] 关键用户验证。

## 6. 切换后

- [ ] 源库保持只读一段时间，作为回滚兜底；
- [ ] 观察 24–72 小时；
- [ ] 记录遗留问题；
- [ ] 确认后再下线源系统。

## 7. 回滚条件

- 数量/金额对账不通过；
- 关键业务不可用；
- 数据错误影响业务；
- 应用错误率显著升高。

回滚步骤：

1. 停止应用新写入；
2. 切回旧库连接；
3. 恢复应用；
4. 记录事故与差异；
5. 修复后重新评估切换。
