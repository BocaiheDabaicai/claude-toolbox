# 切换与回滚

## 1. 切换前

- 迁移计划、映射、对账记录评审完成；
- 源库只读账号可用；
- 目标库连接、权限、磁盘空间确认；
- 目标库备份完成，恢复演练通过；
- 最终增量命令、应用切换命令、回滚命令确认；
- 业务方通知完成。

## 2. 冻结源写入

- 通知业务停止写入；
- 确认无新数据：监控、日志、计数；
- 记录冻结时间；
- 冻结期间源库只读。

## 3. 最终增量

```bash
migration-kit run --config migration.toml --apply
```

- 记录 processed/written/skipped/errors；
- 失败则停止，不带病切换；
- 通过后立即对账。

## 4. 对账

- 数量；
- 金额/汇总；
- 抽样；
- 唯一键/外键/空值；
- 业务关键查询。

任何一项不通过：停下，修复或回滚。

## 5. 切换应用

1. 切换数据库连接/配置；
2. 重启应用；
3. 检查 `/api/healthz`、`/api/readyz`；
4. 检查错误日志、慢查询；
5. 关键用户验证；
6. 通知业务恢复使用。

## 6. 观察期

- 24–72 小时；
- 源库保持只读，不立即下线；
- 监控错误率、慢查询、数据异常；
- 记录遗留问题；
- 确认后再下线源系统。

## 7. 回滚

触发条件：

- 数量/金额对账不通过；
- 关键业务不可用；
- 数据错误影响业务；
- 应用错误率显著升高；
- 业务方要求。

步骤：

1. 停止应用新写入；
2. 切回旧库连接；
3. 恢复应用；
4. 保留新库数据用于分析；
5. 记录事故、差异、时间线；
6. 修复后重新评估切换。

回滚后不要立即删除新库数据；先完成差异分析。

## 8. 沟通模板

```
【数据迁移切换通知】
时间：YYYY-MM-DD HH:MM - HH:MM
影响：系统暂停写入
步骤：冻结 -> 最终迁移 -> 对账 -> 切换 -> 验证
回滚：如验证失败，立即切回旧库
联系人：XXX
```

## 9. 切换清单

- [ ] 备份可恢复；
- [ ] 源写入已冻结；
- [ ] 最终增量成功；
- [ ] 对账通过；
- [ ] 应用切换完成；
- [ ] 健康检查通过；
- [ ] 主链路验证通过；
- [ ] 观察期无异常；
- [ ] 源系统可以下线；
- [ ] 文档归档。
