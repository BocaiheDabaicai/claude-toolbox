# 测试策略

## 1. 原则

- **按风险分配测试**：钱、权限、数据一致性、登录、迁移优先。
- **测试行为，不测实现**：用户能看到的结果，不是内部函数调用次数。
- **少而稳的 E2E**：只覆盖关键链路，不用 E2E 堆覆盖率。
- **确定性**：固定数据、固定时间、固定随机种子；避免 sleep。
- **快速反馈**：单元/组件秒级，API 分钟级，E2E 控制在关键路径。
- **测试即文档**：用例名称说明业务规则。

## 2. 测试金字塔

| 层 | 工具 | 数量 | 关注 |
|---|---|---|---|
| 单元 | Vitest / pytest | 多 | 纯函数、校验、金额、日期 |
| 组件 | Vitest + Vue Test Utils | 中 | 表单、列表、空态、交互 |
| API | pytest + httpx | 中 | 登录、CRUD、错误码、权限 |
| 契约 | OpenAPI/codegen | 少 | 字段与类型一致性 |
| E2E | Playwright | 少 | 登录、主链路、异常态 |
| 回归 | gate.py + 清单 | 每次发布 | 构建、测试、健康检查 |

## 3. 按风险排序

优先测：

1. 登录/权限/越权；
2. 金额/库存/状态流转；
3. 数据迁移/对账；
4. 创建/更新/删除等写操作；
5. 外部集成回调/幂等；
6. 关键查询/报表。

可以少测：

- 纯展示文案；
- 框架已保证的能力；
- 低频且无副作用的页面。

## 4. 环境

| 环境 | 用途 | 数据 |
|---|---|---|
| 本地 | 开发自测 | 本地/内存/测试库 |
| CI | 单元/API/构建 | 临时测试库 |
| 测试/预发 | E2E/回归 | 稳定测试数据 |
| 生产 | 只做冒烟/监控 | 真实数据 |

规则：

- 测试不连生产库；
- E2E 不依赖手工数据；
- 测试账号/密钥不入库；
- 迁移在测试库先跑。

## 5. 测试数据

- 用工厂/seed 生成；
- 每个用例独立数据或用事务回滚；
- 固定业务键，便于断言；
- 清理策略明确；
- 不含真实个人信息。

## 6. 入口/出口

入口：

- 功能达到 `demo`；
- 环境可用；
- 测试数据就绪。

出口：

- P0/P1 用例通过；
- 无阻塞/严重缺陷；
- 回归门禁通过；
- 遗留问题已确认。

## 7. 覆盖率

覆盖率是信号，不是目标：

- 核心业务/金额/权限必须有测试；
- 不为了数字测 getter/setter；
- 覆盖率高但断言弱没有意义；
- 新代码覆盖率优先于存量。

## 8. 分工

- 开发：单元/组件/API；
- 测试/验收：关键链路/E2E/回归；
- 运维：健康检查/发布/回滚验证；
- 业务：验收标准与 UAT。
