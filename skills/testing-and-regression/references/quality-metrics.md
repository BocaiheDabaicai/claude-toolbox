# 质量指标

## 1. 指标

| 指标 | 说明 | 用法 |
|---|---|---|
| 关键链路通过率 | 登录/主业务/E2E | 发布门禁 |
| 单测/组件覆盖 | 核心模块 | 趋势，不追数字 |
| 测试耗时 | 本地/CI | 保持反馈速度 |
| flaky 率 | 偶发失败 | 隔离并修复 |
| 缺陷逃逸 | 上线后发现 | 复盘补测试 |
| 迁移对账差异 | 行数/金额 | 切换门禁 |
| 回滚耗时 | 事故恢复 | 演练 |

## 2. 覆盖策略

- 金额/权限/状态流转/迁移必须有测试；
- 新代码优先；
- 覆盖率下降需要解释；
- 不为覆盖率写无断言测试；
- 关键分支/异常分支优先。

## 3. Flaky

- 记录用例、失败率、原因；
- 去 sleep、隔离数据、固定时间/随机；
- 连续 flaky 先隔离，不阻塞主流程；
- 修复后回归。

## 4. 缺陷逃逸

上线后发现的 bug：

- 补一个能复现的测试；
- 判断是缺测试、缺场景还是需求变更；
- 更新回归清单；
- 不只看“修好了”。

## 5. 测试数据卫生

- 不含真实个人信息；
- 固定账号/固定业务键；
- 用例结束清理；
- 测试库可重建；
- seed 可重复执行。

## 6. 反模式

- 只测 happy path；
- 测试实现细节，重构就挂；
- 用 sleep 等异步；
- E2E 互相依赖；
- 测试连生产；
- 覆盖率造假；
- flaky 长期不修；
- 发布不跑门禁。
