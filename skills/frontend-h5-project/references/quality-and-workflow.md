# 质量门禁与协作流程

## 1. 环境门禁

| 项 | 要求 |
| --- | --- |
| Node | 20.19+ 或 22.12+ |
| pnpm | 9.x，锁定 9.15.9 |
| 包管理器 | 只用 pnpm；禁止 npm / yarn / bun |
| 锁文件 | 不删除、不重建、不手工编辑；只有明确升级依赖时才更新 |
| preinstall | 不要用 `--ignore-scripts` 绕过 `scripts/check-env.mjs` |

安装前检查：

```bash
node -v
pnpm -v
git diff --stat pnpm-lock.yaml   # 应为空
```

常见报错与处理：

- `ERR_PNPM_UNSUPPORTED_ENGINE`：pnpm 版本不对，装 9.15.9；
- 锁文件首行变成 `lockfileVersion: '6.0'` 或大量依赖降级：旧版 pnpm 重写，`git checkout -- pnpm-lock.yaml` 后用 pnpm 9 重装；
- `ERR_PNPM_OUTDATED_LOCKFILE`：先确认改动来源，不要直接删锁文件；
- Node 版本错误：升级 Node。

## 2. 构建门禁

每个阶段收尾至少执行：

```bash
pnpm build
git diff --stat pnpm-lock.yaml
```

要求：

- 构建通过，无未解析导入；
- 锁文件无非预期改动；
- 构建产物中不包含测试密钥、绝对本地路径、调试代码；
- 新增依赖必须确有需要，并同步锁文件（仅在明确升级依赖时）。

## 3. 测试策略

### 3.1 Mock 后端

适合页面开发期，验证：

- 骨架屏 → 内容过渡；
- 空态 / 错误态 / 加载更多；
- 分页、筛选、切 tab 竞态；
- 按钮禁用、二次确认、Toast；
- 图片加载失败兜底。

### 3.2 真实后端

适合联调期，重点确认：

- 登录、token 过期、刷新恢复；
- 请求头（storeId / merchantNo / token）；
- 列表状态与分页字段；
- 金额、库存、订单状态；
- 上传返回值；
- 售后、钱包、积分等字段结构。

### 3.3 浏览器检查

- 宽度：320 / 375 / 414；
- 首屏、二级页、hash 刷新/直开；
- 浏览器返回与 `PageHeader` 返回；
- 底部导航角标、safe-area；
- 控制台无 error / warning；
- 弱网/慢图下的加载体验。

### 3.4 Playwright / 自动化

可用本地 mock 或真实后端跑：

1. 清缓存 → 登录 → 首页；
2. 商品 → 加购 → 购物车 → 结算 → 提交预订单；
3. 订单列表 → 详情 → 确认收货 / 申请售后；
4. 我的 → 个人信息 / 钱包 / 积分；
5. 二级页返回、刷新、hash 直开。

## 4. 回归清单模板

- [ ] 清缓存后登录页图形验证码正常；
- [ ] 账号登录 / 短信登录；
- [ ] token 过期自动回登录；
- [ ] 首页 → 详情 → 加购 → 购物车 → 结算 → 预订单；
- [ ] 订单列表 / 详情 / 确认收货 / 售后；
- [ ] 我的 / 个人信息 / 密码 / 手机号；
- [ ] 钱包 / 充值记录 / 余额明细 / 积分；
- [ ] 文章详情富文本；
- [ ] 四 tab、角标、二级页返回；
- [ ] 图片加载、空态、错误态；
- [ ] 320 / 375 / 414 宽度；
- [ ] 控制台无 error / warning；
- [ ] `pnpm build` 通过，锁文件无漂移。

## 5. 文档与提交

每个阶段收尾：

1. 更新 `docs/roadmap.md` 开发日志与「下一次开工步骤」；
2. 更新受影响的 `docs/backend-contract.md` / `docs/pages.md`；
3. 运行构建与锁文件检查；
4. 询问是否提交。

提交约定：

- 默认只做本地提交，不推送远端（除非用户明确要求）；
- 一个提交只包含一个阶段/一组相关改动；
- 不把用户自己的 `note.md`、环境变量、兄弟项目改动混入提交；
- 提交信息说明「做了什么 + 关键决策」，不要只写“更新”。

## 6. 完成定义（Definition of Done）

一个页面/阶段完成需要同时满足：

- [ ] 主链路可用，空/错/加载态齐全；
- [ ] 真实或 mock 数据验证通过；
- [ ] 移动端宽度、返回、刷新正常；
- [ ] 无控制台报错；
- [ ] `pnpm build` 通过；
- [ ] 锁文件无漂移；
- [ ] 文档与进度已更新；
- [ ] 用户已确认效果（界面类改动）。

## 7. 风险与交接

- 后端风险（未校验归属、库存、分页字段）写入 `backend-contract.md`，不要静默绕过；
- 未完成事项写入 `roadmap.md` 的待确认事项；
- 每次收尾写清「下一次从哪里开始」，保证新会话可接续；
- 大改动前先确认范围与方案，避免一次性重写。

## 8. 不要做的事

- 为了“能跑”删除锁文件或改用 npm/yarn；
- 在页面里吞掉错误、只留 console；
- 用全局 loading 掩盖并发请求问题；
- 直接渲染后端富文本；
- 用浮点数算金额；
- 把测试用的 mock、demo 登录、调试按钮带进生产构建。
